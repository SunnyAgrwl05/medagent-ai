# MedAgent AI

**Your Autonomous Multi-Agent Healthcare Assistant**

MedAgent AI is a production-ready, hackathon-grade healthcare platform built
around five specialized AI agents powered by **Gemini 2.5 Flash**. It pairs a
premium, animated Next.js 15 front end with real streaming AI chat, PDF/image
report analysis, medicine identification, full-duplex voice conversation, and
a health history summarizer.

> ⚠️ **Medical disclaimer**: MedAgent AI provides general educational
> information generated by an AI model. It is not a licensed medical
> professional and does not diagnose conditions. Always consult a qualified
> doctor, pharmacist, or emergency service for real medical concerns.

---

## ✨ Features

- **Symptom Agent** — conversational triage with follow-up questions, possible
  conditions, and an urgency level (Low / Moderate / High / Emergency).
- **Medical Report Agent** — upload a PDF or photo of a lab report; extracts
  text (via `pdf-parse` or Gemini vision) and explains every value in plain
  language, flagging abnormal results.
- **Medicine Agent** — photograph a medicine strip/bottle or type its name to
  get dosage, precautions, side effects, and interactions.
- **Voice Agent** — speak using the Web Speech API; MedAgent AI replies out
  loud via speech synthesis for a hands-free conversation.
- **Health Summary Agent** — turns your consultation history into one
  narrative with trend detection and recommendations.
- **Premium UI** — glassmorphism, floating gradient blobs, Framer Motion
  micro-interactions, streaming markdown chat with a typing caret, dark mode,
  fully responsive.
- **Auth & data** — Clerk-protected routes, Supabase schema for
  conversations/messages/activity, toast notifications, loading skeletons,
  and centralized error handling.

## 🚀 Getting started

### 1. Prerequisites

- Node.js 18.18+ (Node 20 LTS recommended)
- A [Clerk](https://clerk.com) application
- A [Supabase](https://supabase.com) project
- A [Google AI Studio](https://aistudio.google.com/apikey) Gemini API key

### 2. Clone & install

```bash
npm install
```

### 3. Configure environment variables

Copy the example file and fill in your keys:

```bash
cp .env.example .env.local
```

```env
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=pk_test_xxxxx
CLERK_SECRET_KEY=sk_test_xxxxx
NEXT_PUBLIC_CLERK_SIGN_IN_URL=/sign-in
NEXT_PUBLIC_CLERK_SIGN_UP_URL=/sign-up
NEXT_PUBLIC_CLERK_AFTER_SIGN_IN_URL=/dashboard
NEXT_PUBLIC_CLERK_AFTER_SIGN_UP_URL=/dashboard

NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=xxxxx
SUPABASE_SERVICE_ROLE_KEY=xxxxx

GEMINI_API_KEY=xxxxx

NEXT_PUBLIC_APP_URL=http://localhost:3000
```

### 4. Set up Supabase

Open the Supabase SQL editor and run the schema documented at the bottom of
`lib/supabase.ts` (creates `conversations`, `messages`, `activity_log`, and
`health_stats` tables with row-level security policies scoped to the Clerk
`user_id`).

### 5. Run the dev server

```bash
npm run dev
```

Visit **http://localhost:3000**.

### 6. Build & start production

```bash
npm run build
npm run start
```

## ☁️ Deploying to Vercel

1. Push this repository to GitHub/GitLab/Bitbucket.
2. Go to [vercel.com/new](https://vercel.com/new) and import the repo.
3. Vercel auto-detects Next.js — no build config changes needed
   (`vercel.json` is already included).
4. Add all variables from `.env.example` under **Project Settings → Environment
   Variables**.
5. Deploy. Every push to `main` redeploys automatically.

Or from the CLI:

```bash
npm install -g vercel
vercel
vercel --prod
```

## 🔐 Notes on security

- All `/dashboard` and `/api` routes (except webhooks) are protected by
  Clerk's `clerkMiddleware` — unauthenticated requests are redirected/401'd.
- Supabase access uses the service role key only in server-side API routes;
  the browser client uses the anon key and should rely on RLS policies.
- Never commit `.env.local` — it's already in `.gitignore`.

## 🩺 Agent design

Each agent has a dedicated, tightly-scoped system prompt in `lib/gemini.ts`
so responses stay on-task and safety-conscious (cautious language, no false
certainty, clear disclaimers, emergency escalation for red-flag symptoms).
